# Decision Log

- **D-001** — V1 is completely independent of the Heat Control System.
- **D-002** — Use Home Assistant Areas/rooms.
- **D-003** — Scheduler controls HA climate entities.
- **D-004** — V1 UI initially exposes up to four periods/day; storage should not be unnecessarily limited to four.
- **D-005** — V2 learning is a separate layer.
- **D-006** — Three or more repeated meaningful changes are required before a learning candidate.
- **D-007** — V2 initially suggests changes rather than silently applying them.
- **D-008** — Seven independent daily schedules; Weekday, Weekend and All Days are UI grouping/apply mechanisms.
- **D-009** — Persistent schedule data uses HA Store as versioned JSON-serialisable data; runtime state is separate.
- **D-010** — Periods have stable IDs plus friendly_name and user-facing name.
- **D-011** — Persistent V1 configuration contains rooms, HA references, seven daily schedules and settings; runtime state is not persisted there.
- **D-012** — Copying schedules preserves logical period identity.
- **D-013** — Primary V1 editor is a modern visual timeline/editor.
- **D-014** — Horizontal manipulation changes time; vertical manipulation changes temperature; clicking opens precise editing.
- **D-015** — Timeline visually represents temperature between transitions.
- **D-016** — Current time and active scheduled temperature are clearly shown.
- **D-017** — Real-world UX takes priority over implementation convenience.
- **D-018** — PC/tablet is the full scheduler; mobile is rapid remote control.
- **D-019** — Manual changes can be temporary and expire by explicit rule.
- **D-020** — Schedule application/source context may be retained while days remain independent.
- **D-021** — Mobile changes explicitly distinguish temporary from permanent.
- **D-022** — Permanent changes can target current day, weekdays, weekend or all days.
- **D-023** — Mobile temperature changes affect the current active schedule period only.
- **D-024** — Permanent mobile changes affect only the active period across the selected scope.
- **D-025** — Identical daily schedules may be displayed as dynamic Weekdays/Weekend groups; divergence displays individual days.
- **D-026** — Grouped edits apply only to the selected schedule period and do not overwrite other periods.

- **D-028** — When ZEAL is installed and configured, its Zones are the preferred top-level navigation context; ZEAL remains optional.
- **D-029** — The approved `ui_mockup/index.html` is the baseline for visual UX work and should be evolved rather than replaced without a decision.
- **D-030** — UI development is validated against human-facing acceptance tests before production integration implementation.
- **D-031** — In the UI, ZEAL Zone is the preferred top-level navigation when ZEAL is installed; Floor and Room selectors cascade from the selected Zone.
