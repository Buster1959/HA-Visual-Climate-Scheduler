# UX Principles

- Normal operation must not require YAML editing.
- Anything draggable must also support precise typed input.
- Human-readable names should be used wherever useful.
- Do not destroy schedules because a device becomes unavailable.
- Bulk operations must permit later individual editing.
- Current state and next scheduled change should be obvious.
- Mobile is for fast action; PC/tablet is for full schedule design.
- Permanent mobile changes affect the current active period only.
- Temporary overrides must be clearly distinguished from permanent changes.
- Weekday/Weekend grouping should never trap users in an inheritance model.
- Optimise for real-world Home Assistant pinch points.
